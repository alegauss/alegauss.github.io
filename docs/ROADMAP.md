## Done when — AG19

- **Every entry states verifiable availability** Each project has a consistent maturity
  label with source and review date; cards and product pages agree; download,
  source-build and preview actions match actual availability; research entries are not
  presented as unverified stable app releases.

## Done when — AG20

- **Combined filters preserve access to the catalogue** Purpose, platform and maturity
  combine correctly; reset and no-results states work; labels, focus and result
  announcements are accessible; mobile layout works; all projects remain discoverable
  once in prerendered HTML without JavaScript.

## Done when — AG21

- **Cards explain the outcome before implementation details** Every card leads with a
  concrete user benefit and consistent purpose, platform and availability labels;
  technical depth remains on product pages; existing product logos, accents and mobile
  readability are preserved.

## Done when — AG22

- **The method distinguishes documented use from proposed combinations** The page
  explains planning, agent implementation, Windows testing and repeated commits; real
  product examples link to evidence; suggested tracks are labelled accordingly; sourced
  Lab figures remain traceable and no runtime integration is implied.

## Done when — AG23

- **Development relationships have evidence and reciprocal links** Verified built-with
  and used-to-build links come from shared data, include role and evidence, render in
  HTML and Markdown, omit empty or invalid relationships and never imply that end users
  must install the development tools.

## Done when — AG24

- **Products and method precede detailed release activity** The home page explains the
  positioning and method near product discovery, gives AI applications visibility and
  keeps recent updates compact; flagship configuration, full changelog, Atom feeds,
  mobile reading order and Markdown remain valid.

## Done when — AG25

- **Product pages demonstrate capability and offer an accurate next step** Modelado and
  Revelei show authentic useful examples with captions and alt text; the template
  explains audience, outcome, platform, docs and a maturity-appropriate CTA; existing
  design, subdirectory URLs and useful Markdown remain consistent.
